# DDPU_Grading_Book

React SPA для ведення журналу успішності ДДПУ: студенти, викладачі, предмети, групи, оцінки, користувачі та доступи викладачів до предметів. Авторизація працює через Supabase Auth із JWT, дані зберігаються у Supabase Postgres.

## Стек

- React + Vite
- React Router
- Redux Toolkit
- React Final Form / Final Form
- Supabase Auth + Supabase Postgres
- JWT-сесія через Supabase Auth
- Vercel / Netlify конфігурація для деплою SPA

## Основні можливості

- Авторизація користувачів за ролями.
- Захищені маршрути для адміністратора, викладача та студента.
- Публічний каталог предметів, груп і факультетів.
- Табличне відображення даних із пошуком, сортуванням і пагінацією.
- Повноекранні сторінки створення та редагування записів.
- Кастомні випадаючі списки із пошуком для зв'язаних таблиць.
- JavaScript-валідація форм без використання HTML `required`.
- Підтвердження перед видаленням записів.
- Створення облікового запису студента або викладача одразу з форми адміністратора через Vercel API route.
- Demo-режим із локальними seed-даними, якщо `.env` не налаштовано.

## Можливості ролей

### Гість

- Перегляд публічного каталогу навчання.
- Доступ до списку предметів, груп і факультетів.
- Перехід на сторінку входу.
- Не має доступу до особистих, адміністративних і викладацьких сторінок.

### Студент

- Вхід у систему через email і пароль.
- Перегляд персональної панелі.
- Перегляд власних оцінок.
- Пошук, сортування та пагінація у списку власної успішності.
- Перегляд довідкових даних, які потрібні для розшифрування оцінок: предмети, викладачі, типи контролю.
- Без права створення, редагування або видалення записів.

### Викладач

- Вхід у систему через email і пароль.
- Перегляд персональної панелі.
- Перегляд предметів і пов'язаних навчальних даних.
- Перегляд оцінок тільки за власними записами.
- Створення та редагування оцінок для предметів, до яких адміністратор надав доступ.
- Автоматичне підставлення поточного викладача у формі оцінки.
- Вибір студентів, предметів і типів контролю через кастомні списки.
- Пошук, сортування, пагінація та оновлення таблиці оцінок.
- Без доступу до адміністративних сторінок користувачів, груп, факультетів і призначення ролей.

### Адміністратор

- Повний доступ до панелі керування.
- Керування факультетами, спеціальностями, формами навчання та групами.
- Керування студентами і викладачами.
- Введення email і пароля облікового запису під час створення студента або викладача.
- Керування предметами та типами контролю.
- Керування користувачами і ролями.
- Створення, редагування та видалення оцінок.
- Призначення викладачам доступів до предметів.
- Дозвіл або заборона викладачу редагувати оцінки з конкретного предмета.
- Пошук, сортування та пагінація у всіх адміністративних таблицях.

## Структура даних

Основні таблиці Supabase:

- `profiles` - користувачі та ролі.
- `departments` - факультети.
- `specializations` - спеціальності.
- `education_forms` - форми навчання.
- `groups` - групи зі спеціальністю та роками навчання.
- `students` - студенти з прив'язкою до групи, факультету і профілю.
- `teachers` - викладачі з прив'язкою до факультету і профілю.
- `subjects` - предмети.
- `control_types` - типи контролю.
- `teacher_subjects` - доступи викладачів до предметів.
- `success_rate` - оцінки студентів.

## Запуск локально

Не відкривай `index.html` напряму через `file:///`. Це React/Vite SPA, тому сторінка має запускатися через локальний HTTP-сервер.

Найпростіший варіант:

```text
start-dev.bat
```

Або командами:

```bash
npm install
npm run dev
```

Після запуску відкрий:

```text
http://127.0.0.1:5177/
```

Для перевірки production-збірки:

```text
start-preview.bat
```

## Підключення Supabase

1. Створи Supabase project.
2. У SQL Editor виконай `supabase/schema.sql`.
3. У SQL Editor виконай `supabase/seed.sql`.
4. Скопіюй `.env.example` у `.env` і заповни:

```text
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

5. Створи тестові акаунти:

```bash
npm run seed:supabase
```

6. Для production-деплою на Vercel додай server-side змінну `SUPABASE_SERVICE_ROLE_KEY`. Вона потрібна route `api/admin-create-user.js` для створення Auth-користувачів з адмінки.

## Деплой

Для Vercel або Netlify потрібно додати environment variables:

```text
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

Для Vercel також потрібно додати server-side environment variable:

```text
SUPABASE_SERVICE_ROLE_KEY
```

Цей ключ використовується тільки у Vercel API route `api/admin-create-user.js` і не потрапляє у клієнтський JavaScript.

Команда збірки:

```bash
npm run build
```

Папка публікації:

```text
dist
```

`vercel.json` і `netlify.toml` вже додані для коректної роботи SPA-маршрутів.
